# دليل التركيب والتشغيل الشامل لجهاز البصمة الحيوية ZKTeco 9500 / SLK20R
## نظام إدارة المختبرات والتحليل الطبي البيومتري الآمن

يرشدك هذا الدليل خطوة بخطوة لتهيئة وتنصيب قارئ البصمة الحيوية الفعلي من طراز **ZKTeco 9500** أو **ZK SLK20R** وربطه مباشرة بتطبيق الويب عبر الويندوز، وتوصيله بالخادم (Server) والعميل (Client) بنجاح.

---

## 📌 الفكرة الهندسية لعمل النظام البيومتري في المتصفحات
نظرًا لأن المتصفحات (مثل Chrome أو Edge) لا تمتلك صلاحيات وصول مباشرة ومطلقة إلى منافذ الـ USB لأسباب أمنية، فإن النظام يعتمد على **الوكيل البيومتري المحلي (Local Biometric Agent)**:
1. يوضع جهاز البصمة **ZKTeco 9500** في حاسبة العميل (Client) عبر منفذ USB.
2. يتم تشغيل تطبيق خدمي صغير ومحلي (Service/Agent) في الخلفية على حاسوب العميل.
3. يقوم هذا الوكيل بالاستماع على منفذ محلي مغلق وآمن: `ws://127.0.0.1:22001` (بروتوكول WebSocket).
4. عند لمس الحساس بالجهاز، يسحب الوكيل قالب البصمة البيومترية الحقيقية (Template) بصيغة نصية (Base64/Hex/ANSI-378) ويرسلها فوراً إلى المتصفح عبر الـ WebSocket للقيام بعمليات التسجيل والتحقق الفوري بنقرة واحدة (Single-Touch).

---

## 🛠️ الخطوة الأولى: تثبيت تعاريف جهاز البصمة على حاسبة العميل (Driver Installation)
يجب تنصيب التعريفات الرسمية ليتعرف نظام التشغيل Windows على قارئ البصمة **ZKTeco SLK20R / ZK9500**:

1. **تحميل برنامج التعريف**:
   * قم بتحميل حزمة **ZKTeco Biometric Fingerprint Driver v2.0** أو أحدث.
   * [رابط التحميل الرسمي من ZKTeco](https://www.zkteco.com/en/download_cat/Fingerprint_Sensor.html) أو من خلال قرص التعاريف المرفق مع الجهاز.
2. **خطوات التثبيت**:
   * افصل قارئ البصمة من منفذ الـ USB قبل البدء.
   * انقر بزر الفأرة الأيمن على ملف التثبيت `Setup.exe` واختر **تشغيل كمسؤول (Run as Administrator)**.
   * تابع معالج التثبيت حتى النهاية (`Next` -> `Install` -> `Finish`).
3. **توصيل الجهاز والتحقق**:
   * قم بتوصيل جهاز ZK9500 بمنفذ USB 2.0 أو USB 3.0 مباشر في اللوحة الأم للحاسبة (تجنب استخدام الموزعات الخارجية الضعيفة).
   * افتح **إدارة الأجهزة (Device Manager)** في الويندوز.
   * تأكد من ظهور الجهاز تحت تصنيف **Biometric Devices** باسم:
     `ZKTeco Fingerprint Scanner` أو `SLK20R Fingerprint Sensor` ولا توجد بجانبه أي علامة تعجب صفراء.

## 📡 الخطوة الثانية: تثبيت وتشغيل الوكيل المحلي (Local Biometric Agent Setup)
الوكيل هو البرنامج الوسيط الذي يربط القارئ الفعلي بالمتصفح.

1. **المتطلبات التقنية للوكيل**:
   * بيئة تشغيل **.NET Framework 4.5+** أو **Node.js runtime** على حاسبة العميل.
   * استخدام مكتبة **ZKBioSDK / ZKFinger SDK**.
2. **تثبيت وكيل الخدمة (Websocket Service)**:
   * نقوم بتوفير برنامج الوكيل `ZKTecoLocalAgent.exe` (أو تشغيل سكريبت الوكيل المرفق بالخلفية).
   * بمجرد تشغيل الوكيل، سيقوم بفتح منفذ الاستماع المحلي الآمن `22001`.
   * للتحقق من أن الوكيل يعمل، افتح المتصفح واذهب إلى العنوان: `http://127.0.0.1:22001` أو تأكد من إرسال إشارات عبر سطر الأوامر.
3. **التشغيل التلقائي مع الويندوز**:
   * لضمان عدم حاجة الكادر الطبي لتشغيل الوكيل يدوياً في كل مرة، يفضل وضعه في مجلد بدء التشغيل التلقائي (Startup):
     * اضغط على أزرار `Win + R` ثم اكتب `shell:startup` واضغط Enter.
     * ضع اختصار (Shortcut) لملف الخدمة `ZKTecoLocalAgent.exe` داخل هذا المجلد.

## 💻 الخطوة الثالثة: سكريبت العميل للوكيل المحلي (WebSocket Service Script)
في حال كنت تقوم بتجهيز بيئة مخصصة للتطوير والربط، إليك السكريبت البرمجي المصغر للوكيل (والذي يتم تشغيله بلغة Node.js أو كود C# على حاسوب العميل لقراءة البصمة الحية وإرسالها):

```javascript
// ZKTecoLocalAgent.js - يعمل محلياً على حاسوب الممرض/المختبر
const WebSocket = require('ws');
const { ZKFingerSDK } = require('zkteco-node-sdk'); // مكتبة ربط الـ C++ SDK بالـ Node

const wss = new WebSocket.Server({ port: 22001 });
console.log("🔌 ZKTeco Biometric WebSocket Agent running on port 22001...");

wss.on('connection', (ws) => {
  console.log("🟢 Web app connected to local biometric agent.");
  
  // تهيئة مستشعر البصمة ZK9500
  let device = ZKFingerSDK.initialize();
  if (!device) {
    ws.send(JSON.stringify({ event: 'error', message: 'لم يتم العثور على جهاز البصمة ZK9500 متصلاً بالمنفذ!' }));
    return;
  }

  // عند لمس الحساس بالبصمة
  ZKFingerSDK.on('OnCapture', (templateBase64, imageBase64) => {
    console.log("👆 تم التقاط البصمة من الحساس بنجاح!");
    
    // 1. إرسال حدث اللمس وبدء المعالجة
    ws.send(JSON.stringify({
      event: 'OnFingerTouch',
      touchNumber: 1,
      progress: 100
    }));

    // 2. إرسال القالب الرقمي النهائي للبصمة فوراً لتخزينه في قاعدة البيانات
    ws.send(JSON.stringify({
      event: 'enrollment_success',
      template: templateBase64,
      biometricCode: `ZK9500_BIO_${Date.now()}`
    }));
  });

  ws.on('close', () => {
    console.log("🔴 Web app disconnected.");
    ZKFingerSDK.terminate();
  });
});
```

## 🗄️ الخطوة الرابعة: هيكلية قاعدة البيانات وحفظ البصمة على السيرفر (Server/Database)
عند حفظ المريض، يتم إرسال قالب البصمة `fingerprintTemplate` الملتصق من الـ WebSocket كحقل نصي آمن ومتفرد طويل (ANSI-378 / ISO-19794-2) إلى الخادم عبر واجهة API الخاصة بالنظام:

### 1. تخزين البيانات في قاعدة البيانات (SQL Server):
تُحفظ البصمة في جدول الأرشيف الحيوي الآمن `dbo.Lab_Biometrics_Archive`:
```sql
CREATE TABLE dbo.Lab_Biometrics_Archive (
    id VARCHAR(100) PRIMARY KEY,                    -- المعرف الفريد للأرشفة الحيوية
    patientId VARCHAR(100) NOT NULL,                -- معرف المريض الأجنبي (FK)
    fingerprintTemplate VARCHAR(MAX) NOT NULL,      -- قالب البصمة المشفر الممثل كمصفوفة نصية
    nationalIdPhotoBase64 VARCHAR(MAX) NULL,        -- صورة الهوية الوطنية المخزنة
    patientPhotoBase64 VARCHAR(MAX) NULL,           -- الصورة الشخصية المباشرة للمريض
    createdAt DATETIME DEFAULT GETDATE(),
    FOREIGN KEY (patientId) REFERENCES dbo.Lab_Patients(id) ON DELETE CASCADE
);
```

### 2. التحقق والمطابقة البيومترية المباشرة (1:N Matching):
عندما يأتي مريض مجهول الهوية أو عند الحاجة لتأكيد هويته قبل سحب العينة الطبية:
* يلامس المريض جهاز البصمة في سحب العينات.
* يرسل الوكيل المحلي قالب البصمة الحالي الممسوح إلى تطبيق الويب.
* يقوم التطبيق بإرسال القالب الحالي إلى خادم السيرفر لمقارنته مع القوالب المخزنة عبر خوارزمية التطابق الثنائية (Matching Engine SDK) الموجودة على السيرفر، أو يقوم بالمقارنة البيومترية اللحظية الآمنة لفك اللبس وتحديد هوية المريض الحقيقي في أجزاء من الثانية.

## 💡 تم تعديل النظام ليلائم متطلباتك الحقيقية والعملية بالكامل:
1. **الالتقاط من لمسة واحدة (Instant Capture 1/1)**:
   * تم إلغاء التسجيل الثلاثي المعقد (3 قراءات للمطابقة) وتسهيله ليكون **من لمسة وقراءة واحدة فقط** تماماً مثل مرونة الهواتف الحديثة لضمان سرعة إدخال وسحب البيانات دون تعقيد المريض أو الكادر الطبي.
2. **البصمة اختيارية (Optional Biometric)**:
   * أصبح بالإمكان تسجيل المريض وحفظه في السجل الطبي **دون إجبار** على مسح البصمة (اختياري)، وفي حال رغبتك بمسح البصمة يتم قراءتها وحفظها بشكل حقيقي تماماً وصحيح دون توليد أي قوالب عشوائية أو افتراضية كالسابق.
3. **الصوت التنبيهي لنجاح القراءة (Auditory Beep Feedback)**:
   * تم دمج ميزة التنبيه الصوتي الرنان والذكي (Audio Success Beep) عبر المتصفح فور نجاح المسح والالتقاط البيومتري للبصمة لتنبيه الممرض أو أخصائي المختبر بصوت مسموع وواضح دون الحاجة للنظر الدائم للشاشة.

## 📦 الخطوة الخامسة: تجميع النظام والتعريفات في "ملف تنصيبي واحد" (.exe)
لتسهيل تنصيب البصمة على حاسبة الموظف بضغطة زر واحدة ودون تعقيد، قمنا بإنشاء ملف إعدادات برمجية كامل لـ **Inno Setup** (أقوى وأسهل برنامج لتصميم ملفات التثبيت للويندوز).

### 1. المتطلبات البرمجية الواجب تجهيزها على الحاسبة قبل التنصيب:
قبل تشغيل ملف التثبيت الموحد على حاسبة العميل، تأكد من تنصيب المكونات التالية (والتي قمنا بأتمتة فحصها لك):
* **نظام التشغيل**: Windows 10 أو Windows 11 (64-bit).
* **حزم تشغيل Visual C++**: حزمة `Microsoft Visual C++ Redistributable (2015-2022)` مهمة جداً لتمكين نظام التشغيل من قراءة مكتبات الـ DLL الخاصة بشركة ZKTeco.
* **إطار عمل .NET Framework**: تأكد من تفعيل `.NET Framework 4.5` أو أحدث في الويندوز.
* **صلاحيات المسؤول (Admin)**: يجب تشغيل ملف التثبيت بصلاحيات المسؤول لكي يتمكن من تثبيت تعريف الـ USB داخل النظام.

---

### 2. سكريبت الإعداد والفحص التلقائي للمتطلبات (`ZKTeco_9500_Requirements_And_Prereqs.bat`):
لقد قمنا بإنشاء ملف تنفيذي ذكي باسم `ZKTeco_9500_Requirements_And_Prereqs.bat` في جذر المشروع.
* **ماذا يفعل هذا السكريبت؟**
  1. يفحص إذا كان المستخدم قد قام بالتشغيل كمسؤول (Admin) أم لا.
  2. يتحقق برمجياً من توفر حزم .NET Framework المطلوبة.
  3. يقوم **بفتح المنفذ 22001** تلقائياً في جدار حماية الويندوز (Windows Firewall) لضمان اتصال المتصفح بالبصمة دون قيود أو مشاكل شبكية.
  4. يفحص وجود حزم تشغيل الـ C++ اللازمة لربط الحساس الفعلي بالمتصفح.

---

### 3. كيفية بناء ملف التثبيت الواحد (.exe) الخاص بك:
لقد وفرنا لك ملف مشروع كامل مسبق الإعداد والبرمجة باسم `ZKTeco_9500_Installer_Creator.iss`:
1. قم بتحميل وتثبيت برنامج **Inno Setup Compiler** المجاني على حاسوبك [من الرابط الرسمي هنا](https://jrsoftware.org/isdl.php).
2. افتح ملف `ZKTeco_9500_Installer_Creator.iss` باستخدام برنامج Inno Setup.
3. ضع ملفات الوكيل والمكتبات المرتبطة به في نفس المجلد:
   * `ZKTecoLocalAgent.exe` (ملف برنامج الوكيل لخدمة البصمة)
   * `libzkfp.dll` و `zkfpkeep.dll` (ملفات تشغيل SDK الرسمية من ZK)
   * مجلد باسم `drivers` ويحتوي على ملف التعريف الخاص بـ ZKTeco لنواة x64.
4. انقر على زر **Build** أو اضغط على مفتاح **F9** في برنامج Inno Setup.
5. سيقوم البرنامج بإنشاء ملف تنصيبي واحد خارق باسم:
   `ZKTeco_9500_Full_Setup_x64.exe`
6. بمجرد إرسال هذا الملف وتشغيله على جهاز العميل، سيقوم بـ:
   * تنصيب وتثبيت التعريف المناسب للجهاز بشكل **صامت بالكامل (Silent Setup)** في الخلفية دون تدخل بشري على نظام 64-bit.
   * نقل برنامج الوكيل وملفات الـ SDK إلى مجلد الـ Program Files الآمن.
   * **تسجيل البرنامج للعمل والبدء تلقائياً مع إقلاع نظام الويندوز (Auto-startup)** ليعمل دوماً في الخلفية دون حاجة لفتحه يدوياً.

## 🔍 حلول المشاكل الشائعة (Troubleshooting):
* **المشكلة:** يظهر رمز التحذير "الوكيل المحلي غير متصل" في شاشة البصمة.
  * **الحل:** تأكد من تشغيل ملف `ZKTeco_9500_Requirements_And_Prereqs.bat` كمسؤول لفتح المنفذ `22001` في جدار حماية الويندوز (Windows Firewall).
* **المشكلة:** الضوء الأزرق في جهاز ZK9500 لا يضيء عند فتح واجهة البصمة.
  * **الحل:** جهاز البصمة لا يمتلك طاقة كافية. قم بتوصيله بمنفذ USB خلفي مباشر في الحاسوب (USB 3.0 ذو اللون الأزرق)، أو أعد تنصيب التعريف كمسؤول.
* **المشكلة:** الصوت التنبيهي لا يعمل.
  * **الحل:** تتطلب المتصفحات الحديثة تفاعلاً أولياً من المستخدم (نقرة واحدة على الأقل في أي مكان بالصفحة) للسماح بتشغيل الأصوات تلقائياً لحماية خصوصية المستخدمين. تأكد من أن أصوات الحاسبة مفعلة ومستوى الصوت مسموع.
